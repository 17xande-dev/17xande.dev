# 17xande.dev

The site at [17xande.dev](https://17xande.dev): an index of projects, and a
marketing-and-docs section for each one under `/<slug>/`.

| Section                                               | Project                                                           |
| ----------------------------------------------------- | ----------------------------------------------------------------- |
| [`/teleprompter/`](https://17xande.dev/teleprompter/) | [teleprompter](https://github.com/17xande-dev/teleprompter)       |
| [`/web2sdi/`](https://17xande.dev/web2sdi/)           | [web2sdi](https://github.com/17xande/bmd-decklink) (bmd-decklink) |

Static output, no framework, no `node_modules`. TypeScript is bundled by Deno
and the pages are generated by a small build script; it deploys to Cloudflare
Pages.

## Run it

```sh
deno task dev          # build, serve dist/ on :4507, rebuild on change
```

The teleprompter page embeds the **real app** in two iframes. Point them at a
local server rather than production:

```sh
# in the app repo — -dev is what lets localhost frame it
cd ../teleprompter && deno task dev

# here
TELEPROMPTER_APP_ORIGIN=http://localhost:8080 deno task dev
```

Without that variable the demo frames `https://prompter.17xande.dev`.

## Tasks

| Task                  | What it does                                                                 |
| --------------------- | ---------------------------------------------------------------------------- |
| `deno task dev`       | Build, serve, watch                                                          |
| `deno task build`     | Clean build into `dist/`                                                     |
| `deno task sync-docs` | Re-copy the teleprompter repo's `docs/*.md` into `content/teleprompter/docs` |
| `deno task check`     | Type-check `src` and `tools`                                                 |
| `deno task test`      | The docs-link guards                                                         |
| `deno task lint`      | Lint `src` and `tools`                                                       |
| `deno task deploy`    | Publish `dist/` to Cloudflare Pages                                          |

## How it fits together

`src/site.ts` is the registry: the site's name and origin, and one `Project` per
section — its slug, copy, repo, docs and nav. The site index, the header and
footer, the sitemap and the tests all read from it, so adding a project is an
entry there, a `src/pages/<slug>/` with a `home.ts` and a `docsIndex.ts`, its
markdown in `content/<slug>/`, and its screenshots in
`static/<slug>/screenshots/`. The build refuses to run if a registered project
has no section.

`tools/build.ts` is the whole build. It bundles the one browser entry
(`src/scripts/site.ts`), copies `static/`, concatenates the stylesheets, and
generates every page through `src/shell.ts`. Assets are content-hashed so
`/assets/*` can be cached forever.

`deno bundle` is **not** given the HTML as entrypoints: an HTML entry with no
`<script type="module">` gets written to `dist/<basename>`, so every docs page
would land on `dist/index.html` and the last one would win.

### The look

One theme for every section, in `src/styles/site.css`: Fira Code, orange on a
warm near-black, dark only. Fira Code is served from `static/fonts` (OFL, see
`static/fonts/OFL.txt`) rather than Google Fonts, which keeps the CSP free of
third-party origins. Web Awesome's components are themed from the same tokens.

### The docs

Teleprompter's docs are **mirrored, not written here**.
`content/teleprompter/docs/*.md` is a byte-for-byte copy of the app repo's
`docs/`, pulled in by `deno task sync-docs` and committed — Cloudflare Pages
builds from this checkout alone and has no copy of the app repo to read. Keeping
the copy verbatim is what makes `git diff` after a sync a readable record of
what actually changed upstream. **Edit those docs in the app repo**, then sync.

web2sdi's repo has no `docs/` of its own, so its pages are written here in
`content/web2sdi/`, drawn from the repo's `PLAN.md` and source.

Everything that has to differ on a website happens at render time in
`tools/markdown.ts`: relative `themes.md` links become
`/teleprompter/docs/themes/`, links to files this site does not publish go to
the right project's GitHub, and a link whose _text_ is a bare filename is
relabelled with the page's title.

`tools/docs_test.ts` fails if a mirrored doc starts linking to a `.md` this site
does not publish, which is what a rename upstream looks like from here.

### Screenshots

Captured from the real apps at a 1440×900 viewport and 2× DPR, resized to
2048×1280 WebP. The dimensions are written into each page's `SHOTS` so the
browser reserves the space before the image arrives.

### The teleprompter demo

`src/scripts/site.ts` mints a room id in the browser, so every visitor drives
their own demo, and injects the iframes on first intersection. Two things in the
**app** repo make it possible, and breaking either one makes the demo a pair of
blank rectangles:

- `frame-ancestors` in `src/backend/main.go` names this site's origin.
- `src/frontend/scripts/viewer.ts` treats the presence of `?room=` — not the
  absence of framing — as "I am a real viewer".

A framing refusal is only ever reported in **this** page's console, never the
app's logs.

## Deploying

Connect this repository in the Cloudflare Pages dashboard, set the build command
to `deno task build` and the output directory to `dist`, with `DENO_VERSION`
set, and every push deploys on its own.

`static/_headers` carries the CSP, which admits no third-party origin except
`frame-src` for the teleprompter app being framed.

`deno task deploy` is a manual escape hatch: it shells out to `npx wrangler`,
which fetches the CLI on demand and installs nothing permanent. First run needs
`npx wrangler login`.
